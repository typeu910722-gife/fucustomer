# 營利模式：免費＋外觀商城＋限定付費店面

> 狀態（2026-10-20）：**框架和遊戲內介面已完成，還不能真的收錢。** 真正付款要等使用者自己申請各平台的開發者帳號（見下方「要賣東西需要什麼」）。目前所有「購買」按鈕都只會顯示「付款功能準備中，正式上架後開放」。

## 原則

- 遊戲本體免費。**主線劇情（第 1–10 章、每日挑戰、無限夜班）永遠免費**，包含在付費店面裡上班的那幾班。
- **沒有廣告、沒有轉蛋／抽獎箱、沒有付費變強（pay-to-win）**。付費內容只有：外觀、以及「自由營業／自己開店／自己開房」能不能選某些店。
- 外觀大部分用**薪資點數**（上班賺的錢，就是職涯畫面的 💰 存款）購買，不用花真錢。
- 沒有「鑽石」之類的付費貨幣。付費內容是一次買斷的「擴充包」（平台上叫非消耗型商品／DLC），買了就永久擁有。

外觀出現在哪裡：

## 程式架構

| 檔案 | 內容 |
|---|---|
| `shared/shop.ts` | 商品目錄、擴充包、`storeLocked(地圖, 模式, 已購)`（只有 free／own／host 會鎖）、用薪資點數購買、穿戴、`sanitizeShop`、`sanitizeOutfit`（伺服器檢查收到的穿搭） |
| `shared/career.ts` | `CareerProfile.shop = { owned, equipped, entitlements }`；舊存檔沒有這欄會自動補空的 |
| `client/src/billing.ts` | 平台付款介面 `BillingAdapter { available(), purchase(productId), restore() }`；web／electron／android／ios／steam 目前都用 `PendingAdapter`，一律回「付款功能準備中，正式上架後開放」 |
| `client/src/shop-ui.ts` | 職涯畫面「🛍 商城」分頁（3D 試穿預覽、篩選、購買、穿上／卸下、擴充包、恢復購買） |
| `client/src/cosmetics.ts` | 3D 外觀（低多邊形、共用材質；帽子／圍裙花紋／名牌在角色合併成一個網格之前加上去，店面裝飾在店面合併靜態網格之前加上去，幾乎不增加 draw call） |
| `shared/protocol.ts` / `shared/room.ts` | `create`／`join` 訊息可帶 `outfit`（選填，舊版客戶端不送也沒關係，`PROTOCOL_VERSION` 沒變） |

### 測試用解鎖（QA）

網址加上 `?devshop=1`（例如 `https://…/?devshop=1`）會在**這次開頁面**暫時解鎖全部擴充包，方便測試付費店面；不會寫進存檔，商城上方會顯示「🧪 測試模式」。只有這個網址參數能開；正式上架的版本用 `VITE_NO_DEVSHOP=1 npm run build:client` 建置就會完全忽略它。

### 存檔備份（換裝置）與付費內容

設定 → 💾 存檔備份 可以匯出／匯入 `FUC1-` 開頭的存檔碼（`shared/savecode.ts`、`client/src/backup-ui.ts`），不用帳號就能在網頁版、Android、Windows 之間搬進度。

- **擴充包（`shop.entitlements`）不會跟著存檔碼走**：匯出時清空；匯入時一律忽略存檔碼裡的擴充包，保留「這台裝置原本就有」的擴充包。擴充包只能由平台購買／「恢復購買」取得。
- 匯入後，這台裝置沒有的付費外觀（金色店長帽、霓虹圍裙等）會自動卸下。
- 用**薪資點數買的外觀（`shop.owned`）會跟著走**，因為那是玩出來的進度（`sanitizeShop` 本來就只接受有點數價格的商品，付費外觀放進 owned 會被濾掉）。
- 檢查碼只防複製錯誤，不是簽章；職涯進度本來就存在本機、可以被改，跟直接改 localStorage 一樣。正式販售後擴充包仍要靠伺服器驗證購買憑證，不能靠存檔。
- 不包含：Google 登入（`fucustomer.account.v1`）、多人重連資訊（`fucustomer.session.v1`）、自訂伺服器網址。

## 要真的賣東西需要什麼（使用者要自己申請）

以下費用是目前已知的公開資訊，**以各平台官方最新公告為準**：

| 平台 | 需要的帳號 | 費用（以官方為準） | 之後要做的事 |
|---|---|---|---|
| Android | Google Play Console 開發者帳號 | 一次性 US$25 | 在 Play Console 建立 3 個「一次性商品」（對應 3 個擴充包 id），接 Google Play Billing（Capacitor 外掛），伺服器驗證購買憑證 |
| iOS | Apple Developer Program | 每年 US$99 | 在 App Store Connect 建立 3 個「非消耗型 App 內購買項目」，接 StoreKit，必須提供「恢復購買」（介面已有按鈕） |
| Steam（Windows） | Steamworks 合作夥伴帳號 | 每個遊戲 US$100（Steam Direct 上架費） | 擴充包做成 DLC 或用 Steam 微交易，Electron 透過 Steamworks API 查詢擁有權 |
| 網頁版 | 金流服務（例如綠界、藍新、Stripe 等，都要註冊並審核） | 依各家手續費 | 需要伺服器端訂單與驗證；**目前完全沒有做，也沒有註冊任何金流** |

另外各平台抽成（約 15%–30%，依平台與方案而定）、稅務資料、隱私權政策更新（`docs/PRIVACY.md` 要加付款相關說明）都要處理。

## 還沒做的事

- **沒有任何真正的付款**：所有平台都是 `PendingAdapter`，沒有 SDK、沒有金鑰、沒有商品 id 對應。
- **伺服器還不驗證購買**：擴充包和贊助者徽章目前只存在玩家自己的存檔（本機），技術上可以被改。正式販售前要：(1) 購買憑證送到遊戲伺服器驗證；(2) 已購項目跟 Google 登入的證照帳號綁定，換手機可恢復；(3) 多人房間的房主開付費店面時，伺服器要檢查房主的已購項目（目前只有客戶端擋，房主在等候室換店面時也是客戶端擋）。
- 證照上的帽子和贊助徽章是客戶端回報的，伺服器只檢查帽子 id 是否存在，不檢查是否真的擁有。
- 外觀不同步到「好友的店」（搗亂模式看到的店員仍是預設樣子）。
- 價格全部是暫定；擴充包的商品 id 要等平台後台建好才能對應。
- 退款、家長控制（iOS Ask to Buy）、各國稅務都還沒處理。
