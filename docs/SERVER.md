# 連線服務設定

## 架構

- 一個 Node 程序同時提供：靜態網頁（`dist/`）、`/health`、WebSocket `/ws`。
- 遊戲狀態全在伺服器記憶體中；每個營業日開始與日結時把**檢查點**寫到 `DATA_DIR`（預設 `./data/rooms/`）。
- 收到 `SIGTERM`/`SIGINT` 會先寫檢查點、通知玩家再關閉；重啟後 30 分鐘內的檢查點會被恢復，玩家以原房間碼＋重連憑證回到**當天開店前**的狀態。
- 客戶端不含任何密鑰。重連憑證（token）由伺服器隨機產生、只存在該玩家裝置與伺服器檢查點檔案中。

## 本機

```bash
npm run build && npm start   # PORT=8787
```

區網其他裝置：`http://<電腦IP>:8787`。

## 部署（任一支援 WebSocket 的主機）

```bash
docker build -t fucustomer .
docker run -p 8787:8787 -v fucustomer-data:/data fucustomer
```

需求：HTTPS/WSS（手機原生 App 與商店審核要求加密連線）、持久化磁碟（檢查點）、單一執行個體（房間在記憶體中，尚未做多節點分流）。

原生／桌面版建置時以 `VITE_SERVER_URL=wss://你的網域/ws` 指定伺服器；網頁版自動使用同網域。

## 環境變數

| 變數 | 預設 | 說明 |
|---|---|---|
| `PORT` | 8787 | 監聽埠 |
| `DATA_DIR` | ./data/rooms | 檢查點目錄 |
| `STATIC_DIR` | ./dist | 網頁檔案 |
| `MAX_ROOMS` | 500 | 房間上限 |
| `BK_TIME_SCALE` | 1 | **僅測試用**時間加速，正式環境不可設定 |

## 費用與限制（尚未採用任何付費服務）

尚未替你開通任何雲端服務。採用前需要你確認帳號與費用，以下是需要比較的點，**價格會變動、不宣稱永久免費**，請以各家官網當期價格為準：

- 候選：Fly.io、Render、Railway、自架 VPS（如 Hetzner、Linode）、Google Cloud Run（需注意 WebSocket 連線時間上限）。
- 必看條件：WebSocket 長連線是否支援／有無逾時、閒置是否休眠（休眠會讓房間消失）、持久化磁碟、出站流量計費、地區（台灣玩家建議東京/新加坡/台灣節點）。
- 流量估算：每位玩家約 12 次快照/秒，目前為完整 JSON 快照，5 人房約 15–40 KB/s 下行（之後會改差量壓縮）。

## 安全

- 每連線訊息大小上限 4 KB、每秒 80 則；房間碼 5 碼（約 3,300 萬種組合）。
- 所有金錢、庫存、拿取、升級、獎勵由伺服器判定；重送的請求 ID 只生效一次；升級需帶目前等級避免重複購買。
- 尚未實作：帳號系統、檢舉/踢人、DDoS 防護（需由主機前端提供）。
