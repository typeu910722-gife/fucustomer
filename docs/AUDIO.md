# 音效 QA 與混音（第 25 輪）

> **重要：以下全部是儀器量測，沒有任何人實際聽過。** 數字只能證明「沒有削波、沒有 NaN、沒有無聲、響度落在設定範圍」，
> 不能證明好不好聽、搞笑感有沒有保留。請真人用耳機和手機喇叭各聽一次 `docs/audio-reel.ogg`（50 秒，所有音效依序播放）再下結論。

## 量測方法

- 腳本：`node scripts/audio-qa.mjs [標籤] [輸出資料夾]`（預設 `/tmp/claude-0/audio25`）。用 esbuild 把 `tests/e2e/audio-harness.ts` + 真正的 `client/src/audio.ts` 打包成頁面，
  在 headless Chromium 的 `OfflineAudioContext`（48 kHz、單聲道）裡離線算出來，走的是遊戲內同一條混音鏈（含限幅器）。
- `setInterval / setTimeout / performance.now()` 換成虛擬時鐘，用 `OfflineAudioContext.suspend()` 推進，所以音樂排程器和店內環境音的隨機事件都照真實時間跑；`Math.random` 有固定種子，結果可重現。
- 每個聲音前面墊 0.3 秒：Chrome 的 `DynamicsCompressorNode` 剛建立時處在「全壓縮」狀態、要一個 release 時間才放開，若聲音在 t=0 播會被誤壓（遊戲裡 AudioContext 早就在跑，不會發生）。
- 設定用預設值：音效 0.7、主音量 1、音樂 0.5。距離衰減 = 1（玩家自己的動作），`k` = 1。
- 項目：峰值 dBFS、削波樣本數（|x| ≥ 1）、DC 偏移、有聲長度、RMS、K 加權響度（BS.1770：400 ms 瞬時最大值 M-max、3 s 短期最大值 S-max、閘控整合響度 I）、頻譜重心、>6 kHz 能量比（刺耳）、<40 Hz 能量比（超低頻轟鳴）、NaN/Infinity、無聲。
- 「限幅前峰值」= 同一段再算一次、但把 DynamicsCompressor 換成直通（看限幅器到底有沒有在工作）。
- 範圍：48 個 SFX、9 種音樂情境（各 10 秒）、21 家店的環境音（各 12 秒）、27 種奧客的登場警報＋專屬旋律、5 個壓力測試（同一音效每 30 ms 連發、12 種音效同時三連發、大絕＋崩潰＋重低音＋Boss 音樂＋環境音同時）。
- 響度欄：SFX 和壓力測試用 M-max（短音效 400 ms 視窗會偏低，0.1 秒的打擊聲大約比同樣大聲的長音低 5 LU，這是正常的）；音樂和環境音用整合響度 I。

誠實說明修改前的狀況：
- **原本沒有削波，也沒有 NaN／無聲。** 舊版主匯流排已有一顆壓縮器（threshold −14 dB），所以疊加時也沒爆音。
- 真正的問題是 **音量層級**：整體非常小聲（多數 SFX −30 到 −45 LUFS），而且彼此差很多 —— 腳步聲 −65 LUFS（幾乎聽不到）、悲傷長號 −48、群眾「喔～」−40，而重低音 −19。
  音樂 −39～−42 LUFS，環境音從 −40（炸物店的嘶嘶聲）到 −66（書店，聽不到）。
- 舊壓縮器門檻很低（−14 dB、knee 10），單一個打擊聲就會觸發，會把打擊感壓掉，同時把音樂一起往下拉（pumping）。
- 刺耳高頻：早餐店／炸雞／牛排館的環境底噪是 3.5 kHz 高通白噪音（>6 kHz 佔 81%）；`unplug` 的火花聲 53%；`slap` 連發 49%。
- 超低頻：電影院底噪 <40 Hz 佔 18%、書店 12%、旅館 9%（手機喇叭放不出來，耳機上是悶悶的轟鳴）。

## 修改內容（`client/src/audio.ts`）

1. **主匯流排**：`out`（主音量）→ 28 Hz 高通（去 DC／超低頻）→ 15 kHz 低通 → 限幅器（DynamicsCompressor：threshold −4 dB、knee 0、ratio 20、attack 2 ms、release 120 ms）
   → −2.3 dB（抵銷 Chrome 壓縮器自動補償增益，使 −4 dBFS 以下完全不受影響）→ 軟削波 WaveShaper（−3 dBFS 以下完全線性，上限 −1 dBFS）→ 喇叭。
   單一音效永遠不會碰到限幅器；只有很多東西同時響時才會作用，最後一道軟削波保證不會超過 −1 dBFS。
2. **每個音效的增益表 `TRIM`**（dB）：照量測結果調整到目標 —— 重要回饋（收銀、出拳、趕走、奧客警報、失誤、完成）約 −20～−25 LUFS，
   大事件（大絕、升級、成就、勝敗）約 −18～−20，小動作（撿起、放下、補貨、嘿咻、揮手風聲）約 −25～−32，腳步 −34。
   每個音效先過自己的增益節點再進「音效音量」，原本程式裡的相對音色比例都沒改。打擊類的峰值上限 −3.5 dBFS、其他 −5／−8 dBFS，留空間給疊加。
3. **音樂** 匯流排 0.35 → 2.2（× 音樂滑桿）：音樂整合響度約 −28～−30 LUFS，比重要音效低約 6～10 LU。
4. **環境音**：匯流排 0.6 → 2.7，加 45 Hz 高通 + 5.5 kHz 低通，每家店一個 `lvl` 微調，大多落在約 −42 LUFS；書店／旅館／電子店刻意保持更安靜（上限只補 +6 dB，不把低頻轟鳴放大）。
   炸物類底噪改成 3 kHz 帶通（>6 kHz：81% → 約 10%）。循環底噪改用 3.7 秒的噪音（原本 0.6 秒循環聽得出重複）。環境音開始時 0.5 秒淡入。
   順手修：調音樂滑桿時，環境音原本不會即時跟著變，現在會。
5. **連發不疊爆**：每個音效同時最多 3 個聲部（長音效／大事件只允許 1 個），重疊的那一個再自動壓低（1 / (1 + 0.45 × 重疊數)）；原本的 `GAP` 速率限制保留。
6. **防爆音（click）**：噪音類 `noise()`、環境音 `hiss()`、音樂的大鼓和 hi-hat 原本是瞬間起音，改成 5 ms 起音；其他（tone 10 ms、voice 20 ms）原本就有。所有釋放都是指數衰減到 −80 dB 再停。
   音量滑桿改成 15 ms 平滑（拖動時不會有拉鍊聲）。停音樂／環境音的淡出時間常數縮短，斷開前已衰減到約 −50 dB 以下。
7. **刺耳高頻**：`unplug` 火花改帶通 3.2 kHz（53% → 11%）、`cash` 的叮噹亮音改帶通 5 kHz、`slap` 的「啪」改帶通 2.8 kHz（連發 49% → 5%）。

## 還沒做到／需要真人確認

- **沒有人聽過。** 響度目標是依常見遊戲混音習慣訂的，實際「哪個太吵、哪個太小、好不好笑」要人聽。最可能需要微調的：腳步（−34，走路時一直響）、`ooh`／悲傷長號（原本非常小聲，現在拉到正常音量，喜劇效果可能變得太搶戲）、整體比以前大聲約 10 dB（原本預設音量下太小聲，玩家可能已經把系統音量調高了）。
- 量測是單聲道、48 kHz、Chromium；Safari／iOS 的 DynamicsCompressor 和 WaveShaper 實作不同，沒有量。手機喇叭的實際頻響也沒有量。
- 爆音（click）只做了程式層面的檢查（所有起音 ≥ 5 ms、釋放都衰減到 −80 dB 才停），沒有自動偵測器。
- 距離衰減（其他玩家的動作）和 `k`（丟擲力道）沒有逐一量，只量了 `k = 1`、在自己腳邊的情況。
