# 猴子測試（隨機操作測試）報告 — Round 28c

> 誠實標示：這是**一台電腦上的自動隨機測試**（Playwright + Chromium headless、軟體 WebGL／SwiftShader），
> 手機尺寸是用 844×390 + 觸控模擬，**不是實機**；多人是**同一台電腦兩個瀏覽器分頁**，不是兩台裝置。
> 測試時機器同時被其他工作佔用（load 6–15、4 核），遊戲只跑 0.5–9 FPS，所以每一步比真人慢很多。

## 怎麼跑

```bash
# 先開一個伺服器（npm start 或自己的 PORT / STATIC_DIR），再：
GAME_URL=http://127.0.0.1:8787/ npm run test:monkey
# 常用參數
MONKEY_MINUTES=10            # 每個畫面尺寸跑幾分鐘（預設 10）
MONKEY_SEED=400              # 第一個種子（之後每個情境 +1）
MONKEY_SCENARIOS=freeplay,multi
MONKEY_VIEWPORTS=1280x720,844x390
OUT=/tmp/monkey              # 報告 monkey-report.json、每輪的動作紀錄 trace-*.log、發現問題時的截圖 shot-*.png
```

`tests/e2e/monkey.mjs` **不在** `npm run test:e2e` 裡（太久）。重現某個問題：用報告裡的
`seed` + `scenario` + `viewport` 再跑一次。動作序列由種子決定，但遊戲是即時的，所以重跑是「同一種走法」，
不保證每一步完全一樣；`trace-*.log` 有每一步的時間與動作，可以照著手動重做。

### 情境（每個種子跑一個，輪流）

| 情境 | 存檔 | 做什麼 |
|---|---|---|
| menu | 新手／中期／後期／有自己的店（依種子） | 主選單所有按鈕、分頁、畫面與返回 |
| settings | 新手／中期 | 每個選項逐一切換（含字級 130%、兩種色盲模式），再隨機改；130% 時檢查主選單與設定畫面 |
| shop | 後期 | 商城瀏覽、購買、裝備 |
| freeplay | 中期／後期 | 隨機選店面（可能雇小陳）→ 隨機按鍵 WASD/Shift/E/F/G/空白/Q/R/X/1–8/B/Esc/Enter/T/V/K/Tab + 滑鼠 → 日結畫面 |
| story | 新手 1-1／中期 1-2／後期隨機已解鎖班次 | 劇情、班次、結算、法院 |
| challenge | 後期 | 今日挑戰／每週挑戰／特殊營業日 |
| ownstore | 後期 + 自己的店 + 1 間分店 | 自己的店分頁、營業、日結、升級、分店 |
| backup | 中期／後期 | 存檔備份畫面（沒登入，不碰真的雲端），亂貼存檔碼 |
| multi | 兩個瀏覽器分頁 | 開房／加入、等候室設定、準備、開始；營業中表情輪盤、隊友面板、請人離開、交出房主、加減電腦店員 |

為了在幾分鐘內走到「日結／班次結束」，單人遊戲偶爾會用測試掛鉤把模擬時間快轉到這一段結束（動作紀錄寫成 `warp`）。

### 偵測項目

頁面錯誤、console 錯誤、未處理的 Promise 拒絕、HUD／選單文字出現 NaN／undefined／Infinity／[object、
畫面迴圈凍結（10 秒沒有 requestAnimationFrame）、遊戲迴圈凍結（Game.frame 10 秒沒跑、或未暫停時快照時間 12 秒不動；
門檻因為這台機器很慢而放寬）、空白畫面、軟鎖（選單層有東西但沒有可用的控制項、按 Esc 也沒反應）、
按不到的控制項（在畫面外又沒有可捲動的容器／被別的東西蓋住，用瀏覽器自己的命中測試確認）、頁面橫向溢出、
HUD 重要元件重疊或跑出畫面（同一組在連續兩次檢查都出現才算）、localStorage 經過遊戲自己的 sanitize 後會被改掉
（職涯存檔、設定），以及重新整理後進度變少。
短暫的提示卡（新奧客卡、常客卡、吐司訊息、警告、提示列…）蓋到其他元件，另外記成 `hud-overlap-transient`（只供人看，不算失敗）。

## 找到並修好的問題

### #1 設定 → 存檔備份 → 「← 返回設定」丟例外，按鈕沒反應
- 重現：1280×720 menu 種子 1 第 10 步（設定 → 💾 存檔備份 → ← 返回設定）。100% 會發生。
- 原因：`settingsMenu()` 的備份按鈕在**返回時**才呼叫 `collect()` 讀設定表單，但那時畫面已經換成備份畫面，
  `#s-q` 等欄位不存在 → `TypeError: Cannot read properties of null (reading 'value')`，設定畫面回不來。
- 修正：`client/src/ui.ts` 進入備份畫面前先把表單讀起來，返回時用那份（還沒按完成的改動也保留）。
- 測試：`tests/e2e/round28c.mjs` (1)。

### #2 網頁開了遊戲自己的「全螢幕」後，主選單變成 App 用的「🌐 用瀏覽器登入 Google」
- 重現：1280×720 backup 種子 107（設定勾全螢幕 → 回主選單）。手機網頁開始營業時也會自動要求全螢幕，回選單後同樣情況。
- 原因：`isStandaloneWeb()` 用 `(display-mode: fullscreen)` 判斷「加到主畫面的網頁 App」，但一般分頁用 Fullscreen API 全螢幕時這個條件也成立。
- 修正：`client/src/account.ts` 若 `document.fullscreenElement` 存在（是分頁自己進的全螢幕）就不算網頁 App。
  iOS 主畫面（`navigator.standalone`）和 `display-mode: standalone` 不受影響；`tests/e2e/standalone.mjs` 仍通過。
  （限制：瀏覽器按 F11 的全螢幕仍分不出來，維持舊行為。）
- 測試：`tests/e2e/round28c.mjs` (3)。

### #3 「自訂伺服器」亂填的內容會被存起來，下次啟動才被清掉
- 重現：1280×720 settings 種子 101、backup 種子 107（在 #s-url 填非 ws:// 的字 → 完成）。
- 原因：設定畫面原樣存 `serverUrl`，只有載入時 `sanitizeSettings` 才丟掉；在那之前多人模式會拿這串字去連線。
- 修正：`client/src/storage.ts` 抽出 `cleanServerUrl()`，設定畫面存檔時就用它（不是 ws/wss 位址 = 預設伺服器，跟重新載入的結果一樣）。
- 測試：`tests/round28c.test.ts`（單元）＋ `tests/e2e/round28c.mjs` (2)。

### #4 常客卡（#arccard）蓋住新奧客說明卡（#introcard）
- 重現：1280×720 story 種子 104 第 5 步（常客奧客的開場卡和新奧客卡同時出現，桌機重疊約 11px，手機重疊更多）。
- 修正：`client/index.html` CSS：新奧客卡顯示時常客卡先淡出，卡片收起後再出現。
- 測試：`tests/e2e/round28c.mjs` (4)。

### #5 手機 844×390、字級 130% 時，標題畫面左欄（查好友證照、Google 登入）掉出畫面又不能捲
- 重現：844×390 settings 種子 210 第 60 步（設定字級 130% → 回主選單）。`#m-friend` 在 y=371–416（畫面高 390）。
- 修正：`client/index.html` CSS：大字級時 `.ts-left` 跟右邊選單卡一樣可以捲動。
- 測試：`tests/e2e/round28c.mjs` (5)。

### #6 手機第一次進某種店時，店面介紹卡跑出畫面下緣
- 重現：844×390 challenge 種子 415 第 71 步（7-6 雞排店第一次進店），卡片下緣超出畫面，後半段文字看不到。
- 修正：`client/index.html` CSS：矮螢幕（≤520px 高）介紹卡往上移、字小一點、最高不超過畫面。
- 測試：`tests/e2e/round28c.mjs` (6)（100% 與 130% 都在畫面內）。

### #7（讀程式碼時順手修）「店門還沒鎖」按「鎖門再走」等待中又按「不用」
- 原因：等待同步完成後才寫 `#lk-msg`／跳回職涯；如果玩家已經離開這張卡，會讀到 null（未處理的 Promise 拒絕）或把畫面跳走。
- 修正：`client/src/main.ts` 先確認元素還在。
- Round 29c 複查：「確認元素還在」不夠——等待中按「不用」會回到職涯（`#lk-yes` 不在了，所以不會跳），但同步失敗時
  還是用卡片開啟時讀的舊存檔 `p` 寫回去（如果中間玩過一班，進度會被蓋掉）。改成：用畫面代號（見 #10）判斷還在不在這張卡、
  失敗時重新讀存檔再改回未鎖；等待中「鎖門再走」按鈕先停用（不會重複送出）；「不用，就開著」標成返回鍵（Esc／B）。
  有自動測試了：`tests/e2e/round29c.mjs` (3)（回應延遲 2.5 秒，按完鎖門 → Esc → 離開職涯 → 回應到了仍停在主選單、存檔是已鎖）。

### #8（Round 29c）手機每週挑戰標題很長時，營業狀態列和「開始上班」按鈕重疊
- 位置：營業中上方的狀態列（`#shiftbar`）。每週挑戰標題是「每週挑戰・玩法・店名」，碰到特殊營業日還會再加一段；
  手機上標題換行，狀態列變高，下緣蓋到下面的「▶ 開始上班」按鈕（約 15px）。另外量到：就算標題不換行，
  手機 100% 時狀態列下緣（86px）也和按鈕上緣（85px）重疊 1px。
- 修正：`client/index.html` 狀態列第一行不換行，標題太長就用「…」截掉，計時不會被壓縮；手機營業中「開始上班」那一列往下移 2px（80→82px）。
  注意：這兩行 CSS 在營業中 HUD 區，同時有另一個工作在改手機 HUD 版面，合併時要留意。
- 測試：`tests/e2e/round29c.mjs` (1)：844×390、字級 100% 與 130%，強制塞一個比現有任何組合都長的標題，用 bounding box 確認
  狀態列和計時都不碰到按鈕；同一個測試把舊的換行樣式加回去會量到重疊（bar 下緣 100 > 按鈕 87），證明這個檢查抓得到。

### #9（Round 29c）App 登入連結卡不能用 Esc 關；選單卡片 Esc／手把 B 不一致
- 原因：選單畫面根本沒有處理 Esc（只有營業中的暫停選單會）；手把 B 找返回鍵只看 `#ui`，但 App 登入連結卡（`#applink`）
  是直接掛在 `<body>` 上的，所以手把摸不到它：十字鍵和 A 還在下面的主選單上移動、按鈕，B 沒有作用。
- 修正：`client/src/padnav.ts` 有 `#applink` 這種蓋在最上面的卡片時，手把只在這張卡裡移動、B 按它的返回鍵；
  新增 `escBack()`：Esc 在選單（沒有在營業）時按目前最上層卡片的返回鍵（`data-back`，或看起來像返回的按鈕），
  沒有返回鍵的畫面（主選單、劇情）Esc 什麼都不做，不會像 B 一樣退回主選單。
  另外 Android 返回鍵：登入連結卡開著時先關卡片（之前在主選單上會直接離開 App）。
  主選單 Google 登入／登出完成後，只有畫面還是主選單才重畫。
  明確標上 `data-back` 的按鈕：App 登入卡全部的「取消／關閉」、職涯「← 主選單」、多人「← 主選單」、選店「← 返回」、
  邀請「← 先回主選單」、查好友證照「← 返回」、訊息卡的確定鈕（之前 B 會跳過它的後續動作直接回主選單）、
  「店門還沒鎖」的「不用，就開著」、好友店鎖門的「算了」。設定、存檔備份原本就有。
  刻意**沒有**標：上班結果畫面的「回職涯」、法院「離開法院」（營業中狂按 Esc 叫暫停選單時剛好下班，不該把結果畫面直接跳掉）。
- 測試：`tests/e2e/round29c.mjs` (2)：用 `window.Capacitor` 假裝是 App（跟 round19/25 一樣是模擬，不是真機），
  Esc 關卡片、關掉後不再輪詢、手把 B（`navigator.getGamepads` 模擬）也能關、「準備中…」時按 Esc 關掉後晚到的回應不會再打開；
  查好友證照／號角／職涯／設定按 Esc 都回主選單。

### #10（Round 29c）網路回應晚到時把玩家拉回原本的畫面
- 原因：職涯「自己的店」的上傳／鎖門／搗亂報告，等伺服器回應後一律重畫職涯「自己的店」，就算玩家已經離開；
  鎖門和搗亂報告還會用按下去那時讀的舊存檔寫回（中間如果玩了一班，進度會被蓋掉）。同樣的問題也在：
  主選單 Google 登入／登出完成後重畫主選單（改成只有還在主選單才重畫）、商城購買／恢復購買完成後重畫商城（也用舊存檔）、
  去好友店「找店中…」與「在門口丟垃圾」、搗亂結束送分數、查好友證照的結果、存檔備份的雲端上傳／還原／刪除、「複製」（離開後會丟例外）、讀取 .txt。
- 修正：`client/src/ui.ts` 新增 `screenToken()`：每次換畫面（`show()`／`hide()`）都會讓舊代號失效；
  上面每個等網路的地方，等之前拿代號、回來先檢查，**資料照樣存**（店碼、鎖門、搗亂損失、購買、零用錢），只是不重畫畫面。
  存檔一律在回應後重新讀取再改。離開時才回來的搗亂報告，下次打開「自己的店」分頁時顯示。
- 測試：`tests/e2e/round29c.mjs` (3)：用 Playwright `page.route` 把 /api/stores 的回應延遲 2.5 秒；上傳、鎖門後離開職涯、
  搗亂報告後切到「技能」分頁，回應到了都留在原地，而且店碼、已鎖、−$150 都有存進去。
  （商城購買、Google 登入、丟垃圾、存檔備份這幾條是同樣的寫法，沒有各自的自動測試。）

驗證：#1–#5 的回歸測試在**修正前的版本**（HEAD 另外建置）上會失敗、修正後通過；#6 修正前的失敗是猴子測試截圖看到的，回歸測試只在修正後版本跑過。

## 沒有修的（以及原因）

- **手機上短暫提示蓋住觸控按鈕**：常客卡（觸控版放右上，準備階段約 14 秒）、吐司訊息、警告、提示列、新奧客卡會蓋到
  揍／抓起／旋風／退散等按鈕或計時列。這些卡都是 `pointer-events: none`，**點擊仍會穿過去按到按鈕**，只是看不到。
  觸控按鈕與提示的版面另一個工作正在改（手把／觸控提示），為避免衝突只回報不改。建議：觸控版常客卡改放左側或縮短顯示時間。
- **互動提示（#prompt）和新奧客卡重疊**：新奧客卡最多 4.2 秒，暫不處理。
- 這台機器很慢，凍結門檻放寬到 10–12 秒，**比這短的卡頓抓不到**；FPS 數字也不能當效能參考。
- 猴子測試在遊戲中偶爾回報「按鈕被 canvas 蓋住」，查證是 Playwright 在 1–5 FPS 下判斷元素「不穩定」造成的誤報
  （瀏覽器命中測試確認按鈕在最上層），已在測試裡用命中測試排除。
